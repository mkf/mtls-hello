## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No deps.
- **Foundational (Phase 2)**: Depends on Setup. T002, T003 parallel (different files). BLOCKS US1 and US3.
- **US1 (Phase 3)**: Depends on Foundational T003. Tests T004-T006 before impl T007.
- **US2 (Phase 4)**: Depends on US1 (must remove CA AFTER install generates certs). T008-T010 parallel.
- **US3 (Phase 5)**: Depends on Foundational T002 (helper). T011-T015 sequential (same file).
- **Polish (Phase 6)**: Depends on all.

### Parallel Opportunities

```
T002 (helper, smoke.bats) ─┐ Foundational, different files
T003 (install.sh)         ─┘

T004 (test: generates) ─┐
T005 (test: no overwrite)─┤ US1 tests, parallel (independent fixtures)
T006 (test: no openssl) ─┘

T008 (rm gen_certs.sh) ─┐
T009 (rm certs/)        ─┤ US2 impl, parallel
T010 (rm justfile line) ─┘
```

### Note on ordering constraint

US2 (delete CA) MUST happen after US1 (install generates certs). If the CA files are deleted first, the existing install tests that verify the current behavior would break. US2 can also be done in parallel with US3 as long as US1 is done.

## Notes

- T002 and T003 are both foundational and parallel — they touch different files (smoke.bats vs install.sh)
- The `mkfixture_certs` helper uses 1-day validity so certs never expire mid-test-suite
- `curl --cacert "$SERVER_CERT"` replaces `--cacert certs/certs/ca.crt` — the server's self-signed cert IS the trust anchor
- Existing install tests (feature 007/009) will need `certs/` available until US2 deletes it — do US1 first, then US2/US3
