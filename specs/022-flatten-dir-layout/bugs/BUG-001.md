# Bug Report: cleanup_pkgroot leaves per-distro metadata, warning on every package build

**Type**: Implementation drift (with an untested-flow component)
**Severity**: Low
**Feature**: 022-flatten-dir-layout
**Reported**: 2026-08-06
**Status**: Patched
**Patched**: 2026-08-06

## Description

Running `just package-docker` (Debian then Arch builds) succeeds but the
`cleanup_pkgroot` trap fires warnings on every build:

```
Built /out/mtls-hello_0.1.4_amd64.deb
rmdir: failed to remove /tmp/tmp.hHEd3WkuTD: Directory not empty
warning: could not rmdir /tmp/tmp.hHEd3WkuTD
...
Built /out/mtls-hello-0.1.4-1-x86_64.pkg.tar.zst
rmdir: failed to remove /tmp/tmp.tGldbDbWAf: Directory not empty
warning: could not rmdir /tmp/tmp.tGldbDbWAf
```

The builds still succeed; the scratch `pkgroot` dirs leak in `/tmp` and warn.

## Artifact Traceability

### spec.md

- **Affected user story**: US3 — "Automatic, non-interactive migration" (the
  safe-deletion requirement this cleanup implements is part of the flattening
  change; `cleanup_pkgroot` was introduced by the same sweep).
- **Affected requirements**: FR-005 (migration MUST remove empty directories
  and MUST NOT fail); the safe-deletion helpers it depends on are not spec'd
  directly but are an implementation consequence of the "never purge by
  accident" constraint.
- **Gap identified**: The spec does not cover package-build scratch cleanup.
  The bug is not a spec omission per se — it is that `cleanup_pkgroot` does
  not know about the per-distro metadata files that the *package scripts*
  (not the migration) create.

### plan.md

- **Affected sections**: "Implementation details" — `scripts/package-common.sh`
  update (cert gen / layout), and the safety-sweep helper `cleanup_pkgroot`.
- **Impact**: `cleanup_pkgroot` must also remove the per-distro files created
  by `package-debian.sh` (`$pkgroot/DEBIAN/{control,postinst}`) and
  `package-arch.sh` (`$pkgroot/.PKGINFO`, `$pkgroot/.INSTALL`) before rmdir'ing
  the tree, or the package scripts must place these under paths the cleanup
  already knows.

## Root Cause Analysis

During the "never `rm -rf`" sweep, `cleanup_pkgroot` was written to remove
exactly the files laid out by `stage_install_tree` (usr/bin, usr/lib/systemd,
var/lib/mtls-hello/{handlers,scripts}). But `package-debian.sh` and
`package-arch.sh` add per-distro metadata **after** staging — `DEBIAN/` and
`.PKGINFO`/`.INSTALL` — which `cleanup_pkgroot` does not know about. The
helpers correctly refused to delete unknown content and printed the warning,
which is the designed safe behavior; the gap is that these files are not
"unknown" — the package scripts created them and `cleanup_pkgroot` should
account for them.

## Recommended Fix

1. Extend `cleanup_pkgroot` in `scripts/package-common.sh` to remove the
   known per-distro metadata:
   - `remove_file_safe "$root"/DEBIAN/control "$root"/DEBIAN/postinst`
   - `remove_file_safe "$root"/.PKGINFO "$root"/.INSTALL`
   - `rmdir -- "$root"/DEBIAN` (after emptying it)
2. Add a regression check (a BATS case or a small `package-common.sh`-level
   test) that stages a full per-distro `pkgroot` (usr/ + var/ + DEBIAN/ or
   `.PKGINFO`/`.INSTALL`) and asserts `cleanup_pkgroot` leaves nothing behind
   and prints no warnings.
3. Re-run `just package-docker` and confirm no `could not rmdir` warnings.
4. Update `tasks.md` (reopen T027 or add a task) to note the runtime
   package-cleanup verification.
