# Bug Report: Bare-repo sync BATS tests fail after bundle spooling rewrite

**Type**: Implementation drift / Untested flow
**Severity**: High
**Feature**: 016-bundle-spooling
**Reported**: 2026-08-06

## Description

The feature 016 implementation rewrote `handlers/bundle.post.sh` to spool incoming bundles instead of applying them to bare repositories immediately. However, the existing bare-repo sync BATS tests (tests 14–17 in `tests/smoke.bats`) still assert that the bare repository is updated immediately after the discovery callback runs. Because the bundles now sit in `<data-dir>/spool/<repo>/` until `scripts/merge-spool.sh` is invoked, those assertions fail.

The failing tests are:

- **Test 14**: `US1: bare-repo sync — all branches, tags, and diverged branches`
- **Test 15**: `US1: bare-repo sync works with fully symlinked REPOS_ROOT`
- **Test 16**: `US2: broken symlink under REPOS_ROOT fails cleanly`
- **Test 17**: `US2: repeated bare-repo sync is idempotent`

(Tests 14–16 currently fail; test 17 may pass on some runs because repeated sync with no new bundles does not require applying, but the test still needs the spool→merge cycle to be deterministic and correct.)

The implementation is correct per the feature 016 specification, but the test suite drifted away from the intended workflow: `bundle.post.sh` spools, and the operator (or the test) must call `merge-spool.sh` to apply the bundles.

## Root Cause Analysis

The feature 016 implementation changed the contract between the server and the repository: the server is no longer the actor that modifies `refs/heads/*`. Instead, it only writes to the spool directory, and a separate operator-invoked script (`merge-spool.sh`) performs the actual repository updates. The bare-repo sync tests predate this change and were not updated to include the merge step. This is an implementation drift in the test suite relative to the spec, not a bug in the bundle handler itself.

## Recommended Fix

1. Update tests 14–17 in `tests/smoke.bats` so that after the discovery callback runs (and `bundle.post.sh` has spooled the bundles), the tests call `bash scripts/merge-spool.sh` before checking the repository refs.
2. Complete T007 and T008 by adding the dedicated `merge-spool.sh` BATS tests described in `tasks.md`.
3. Run `/speckit.bugfix.patch` to update the spec artifacts (mark T007/T008 as in progress and add a note about updating tests 14–17).
4. Run `/speckit.bugfix.verify` to confirm the spec and tests are consistent.
5. Resume `/speckit.implement` to apply the test changes.

## Resolution

As of the current state, tests 14–17 in `tests/smoke.bats` already include the
required `scripts/merge-spool.sh` calls after each `on-discover.sh` invocation.
The spool→merge workflow is therefore exercised by the bare-repo sync tests and
the implementation drift described above is resolved in the test suite.
